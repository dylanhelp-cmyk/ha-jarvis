# Voice PE acoustic test firmware

For repository-managed updates, save `voice-pe-repository.yaml` in ESPHome Builder once. It downloads the shared package and custom component from [ha-jarvis](https://github.com/dylanhelp-cmyk/ha-jarvis) on `main`, checking for changes during validation/compilation when the five-minute cache expires. Future source revisions require no file copying: validate, compile and choose Install in Builder. Nothing automatically flashes the device. Tested baseline: **ESPHome 2026.10.0 / ESP-IDF 5.5.6**, for Home Assistant Voice Preview Edition hardware; project version **0.1.3**.

Add the keys in `secrets.example.yaml` to Builder's `secrets.yaml`: Wi-Fi, fresh API encryption key, unique OTA password, App LAN URL (`ws://HA_LAN_IP:8099/device`) and App-generated pairing token. Replace the intentionally invalid all-zero API example. This milestone authenticates over **plain LAN WebSocket**; keep port 8099 private.

Secrets stay in the local entry and Builder's local `secrets.yaml`; the remotely downloaded package and hardware YAML contain no secret lookups. Keep the device name stable across updates. For a fixed-source fallback, copy this complete firmware directory, preserving `components/jarvis_stream/`, and open `voice-pe-testbench.yaml` instead.

Run **Validate**, then **Install → Manual download** for a review candidate. No firmware was flashed or installed. Flashing/acoustic tests remain user-controlled. Native API, OTA, mute, LEDs and local Hey Jarvis are supported; this input-test configuration replaces the stock pipeline/player and keeps the speaker amp off.

Hardware derives from [official Voice PE YAML](https://github.com/esphome/home-assistant-voice-pe/blob/d4e6fa43d6a1a7d342b7d4d403567e06516719de/home-assistant-voice.yaml) at `d4e6fa43d6a1a7d342b7d4d403567e06516719de`, including its license. The same commit supplies `voice_kit`. [XMOS v1.3.1](https://github.com/esphome/voice-kit-xmos-firmware/releases/tag/v1.3.1) implements `NONE/AEC/IC/NS/AGC` selection. **On future first boot, upstream automatically updates XMOS if its version differs**, with its checksum-verified official image.

PCM channel 0 selects `NONE` before AEC/IC/NS/AGC, with unity gain and no ESPHome DC correction. Supported `MicrophoneSource` converts 32-bit stereo I2S to mono PCM16LE. Capture requires actual XMOS 1.3.1 and `NONE` readback. Channel 1 uses `NS`/gain 4 for Hey Jarvis, pinned to official model commit `40ff33f57f8fc6ad71a75ef085abbf742495b225` (upstream Apache-2.0). Wake never starts upload.

Only explicit App tests upload PCM, bounded to 120 seconds. Mute, center button, disconnect, fault or timeout stop capture; reconnect never resumes it. LEDs: red muted, blue capturing, dim white paired/raw verified, amber not ready, brief green wake. Clear center-button mute through Home Assistant's software mute switch.

Espressif `esp_websocket_client` 1.7.0 is pinned at `b2b86d7388de0d7335ff21df1cc15e6ea278caf1`, including its task-completion race fix. WebSocket initialization, sends and teardown run in a dedicated worker; the ESPHome main loop and OTA shutdown do not wait on network operations. Connection starts after network readiness, and library reconnects handle ordinary errors and clean closure. The App's JSON controls and 24-byte little-endian `<4sBBHIQI` PCM header are unchanged. Controls must be single text frames under 768 bytes. Counters expose drops; stale audio is never replayed across captures.

Firmware 0.1.3 enables `CONFIG_ESP_WS_CLIENT_SEPARATE_TX_LOCK` so receive-side waits do not occupy the PCM sender's transmit mutex. The existing 30 ms PCM and 100 ms control send timeouts remain bounded in the worker; microphone callbacks still enqueue without waiting. Heartbeat writes still share the transmit mutex, and genuine network/send failures still reset the transport. A reset now logs the failed message kind and byte count. This addresses a concrete contention hazard; it does not establish the cause of any particular hardware cancellation.

Timestamps estimate first-sample time from callback minus block duration; **XMOS/I2S delay remains uncalibrated**. Clock sync uses the same 32-bit monotonic millisecond epoch (49-day wrap). Raw PCM is not calibrated SPL. Missing frames/poor sync invalidate measurements. Physical mute, audio quality, wake accuracy and wireless reliability remain untested.

Firmware 0.1.3 passed configuration/code generation and full ESP32-S3 compilation/linking on ESPHome 2026.10.0 / ESP-IDF 5.5.6 (1,461,571-byte image; 38.6% static RAM). Generated SDK configuration confirms the separate transmit mutex is enabled. Host regressions cover that SDK option, no-Wi-Fi startup, failed starts, offline/reconnecting behavior, Wi-Fi flaps and worker shutdown. The capture cancellation's hardware cause remains unverified. Dummy secrets and generated credential-bearing source were removed; no device was contacted. Development images are **not installation artifacts**; rebuild your existing local entry in Builder.
